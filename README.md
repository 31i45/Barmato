# Winmato

[![CI](https://github.com/31i45/Winmato/actions/workflows/ci.yml/badge.svg)](https://github.com/31i45/Winmato/actions/workflows/ci.yml)

> Win + Tomato — 极简环境式番茄钟 for Windows

Winmato 把番茄钟编码进托盘图标本身：**自适应任务栏厚度的 2×2 格阵**（启动时按任务栏实际厚度取最大可用尺寸，失败回退 SM_CXSMICON；任意 DPI 下 1:1 渲染最锐利）——四格 ≡ 4 个专注番茄，格位 = 番茄序，灌注高度 = 当前阶段进度，色相 = 阶段，每格 1px 边框永存。没有弹窗、没有数字、没有声音——仅靠余光感知当前处于专注还是休息。

## 更名说明（v2.1）

原名 **Barmato** = Bar + Tomato，其中 Bar 指任务栏，是旧方案（任务栏染色 / 开始按钮覆盖）的载体。T 方案落地后，唯一可视化表面变为 **Windows 托盘图标**，Bar 语义已不复存在，故一对一替换 Bar → Win，保留 -mato（Tomato 词尾）。可执行文件、配置目录、互斥量、窗口类名等全部标识同步更名。

## 特性

- **托盘图标即可视化**：2×2 四格嵌入番茄语义——已完成格实心着色，当前格底部灌注进度，未来格灰色轮廓；边框永存，填充不吞没边框
- **待填充待机**：一轮结束（自然走完长休，或在长休暂停后再点一次收束本轮）即回归四格空心待填充态，悬停提示「本轮已完成」；新周期由你手动开启——完成与否不改变待机视觉，零特殊分支
- **任务栏厚度自适应**：画布取任务栏实际厚度 − 8px（Win11@100% 得 40px、@150% 得 64px），失败回退 SM_CXSMICON；任意 DPI 下渲染与显示 1:1
- **色彩完全自控**：不依赖 alpha 叠加或系统元素，色相辨识度高
- **零外部几何依赖**：不定位任务栏、不覆盖开始按钮、不创建分层窗口——托盘图标是应用自有的唯一视觉表面
- **任意任务栏配置**：居中/靠左/侧边/顶部/自动隐藏，均正常工作
- **边界脉冲与暂停呼吸**：阶段切换瞬间 2.5s 慢脉冲一次；暂停时降亮 50% + 12s 慢呼吸 + 居中放大暂停符号 ❚❚（阶段色恒满亮度，一眼可辨）
- **应用图标资产化**：exe 图标为用户手工设计的 Winmato.ico（多尺寸整帧品牌资产，构建期经 winres 嵌入）；托盘实时图标仍由代码渲染——静态品牌与动态状态分离
- **极简交互**：左键点击托盘图标启停切换，右键退出，仅此而已
- **零干扰**：无弹窗、无通知、无音效、无统计、无设置窗口
- **静默降级**：配置缺失静默回退默认值；不崩溃、不弹窗
- **极致轻量**：纯 Rust 原生，Release 构建约 0.8MB（含多档应用图标资产），待机时停止一切绘制

## 快速开始

### 下载（推荐）

前往 [Releases](https://github.com/31i45/Winmato/releases) 下载最新版，两种格式任选：

- `Winmato.exe` — 单文件即下即用（浏览器可能提示"不常见下载"，选择保留即可）
- `Winmato.zip` — 压缩包，下载拦截风险最低

解压（如选 zip）后直接运行 `Winmato.exe`：单文件、零安装、零依赖。

### 构建

```bash
cargo build --release
```

可执行文件位于 `target/release/winmato.exe`。

### 使用

1. 双击 `winmato.exe` 启动（待机时托盘为四格灰色空心轮廓，低存在感但恒可点击）
2. **左键点击**托盘图标 → 启动番茄周期（第一格开始从底部灌注专注色相）
3. 再次左键 → 暂停（格阵降亮 + 慢呼吸 + 居中暂停符号 ❚❚）；再左键 → 继续
4. 一轮结束：完整走完 4 个专注番茄 + 长休（或在长休暂停后再点一次收束本轮）→ 图标回到四格空心待填充态，悬停可见「本轮已完成」提示；随时左键开启新一轮
5. **右键点击**托盘图标 → 退出

### 配置（可选）

Winmato 无需任何配置即可使用，默认时长为标准番茄钟（25/5/20 分钟）。

高级用户可创建 `%APPDATA%\Winmato\config.json` 自定义时长和配色：

```json
{
  "durations": {
    "focus": 1500,
    "short_break": 300,
    "long_break": 1200
  },
  "colors": {
    "focus": "#2D8C53",
    "short_break": "#47B3B3",
    "long_break": "#5585C8"
  }
}
```

时长单位为秒。配置文件缺失或格式错误时静默回退默认值。

## 视觉设计

**托盘图标四格可视化（T 方案）**：画布自适应任务栏厚度（启动时只读一次，短边 − 8px，失败回退 SM_CXSMICON）渲染 2×2 格阵，几何按比例参数化（方格 = size/3、间距 = max(size/16, 1)、居中偏移），保留"四格 ≡ 四番茄"的语义同构。

| 阶段 | 颜色 | 含义 |
|---|---|---|
| Focus | 深绿 `#2D8C53` | 深度专注中 |
| Short Break | 薄荷青 `#47B3B3` | 短暂休息 |
| Long Break | 天蓝 `#5585C8` | 长休息，周期将结束 |
| 暂停 | 原色相降亮 50% + 12s 慢呼吸 + 暂停符号 ❚❚（阶段色、恒满亮度） | 时间冻结 |

渲染规则：
- **专注 N**：格 1..N−1 实心专注色，第 N 格底部灌注专注色相（高度 = 进度）
- **休息 N**：格 1..N 实心专注色（已获得），第 N 格灌注休息色相
- **待机**：四格均为灰色空心轮廓（待填充）；完成与否不改变待机视觉——完成信息由悬停提示承载，零特殊分支
- **应用图标资产化**：exe 图标采用用户设计的 Winmato.ico 静态资产；程序化生成器已退役——任意显示尺寸下的重采样会丢失细线特征，且系统图标缓存会掩盖真实资产
- **边框永存**：每格 1px 轮廓恒在，实心/灌注仅画边框内区，任何状态下不被吞没
- 阶段切换时 0.6s 平滑色彩过渡 + 2.5s 边界脉冲，无突变

## 架构

```
main.rs               薄主线：消息循环 + 托盘事件 + 定时驱动 + 渲染调度
lib.rs                库入口：领域模块收敛（cycle / icon / colors / config）
cycle.rs              周期状态机：纯业务逻辑，零 Windows API 依赖
icon.rs               托盘图标渲染器：2×2 格阵 + 动画（纯函数 → RGBA 像素）
colors.rs             色彩模块：RGB 运算、配色、插值
config.rs             配置加载：只读 JSON，静默回退
Winmato.ico          用户手工设计的品牌图标资产（build.rs 经 winres 嵌入 exe）
docs/                 需求文档与架构设计文档
```

设计准则遵循《软件设计的哲学（第二版）》：深模块浅接口、最小化状态、围绕不变量设计、消除特殊场景。

## 技术栈

- **Rust** + **windows-rs 0.58** — 原生 Windows API
- **tray-icon 0.19** — 系统托盘（图标渲染 + 左右键事件）
- **serde / serde_json** — 轻量配置解析
- **winres** — 构建时嵌入应用图标资源

## 写在最后：一次关于 AI 编程的反思

这个项目的架构决策与关键设计由人主导完成，AI 只承担被明确限定的执行。这不是姿态，而是用代价换来的认知。

就在这个几百行的小项目上，AI 编程曾一天烧掉一个月的订阅额度。根因不在工具，而在分工：使用者对每种方案与思路的局限性缺乏判断，却把思考与设计一并外包给 AI——它便只能用大量试错代替思考，而每一次方案推翻，都是真实的 token、算力与时间。

AI 确有极强的代码生成能力，那来自对海量开源代码的学习。但大模型本质上是概率模型，而过去几十年的代码与文档，绝大多数本就平庸甚至糟糕——概率模型学到的，是平庸的均值。指望它高效、自主地完成全流程开发，得到的只会是高昂的算力账单和远低于预期的质量；不少公司放弃 AI 编程，原因无非两条：算力成本扛不住，复杂项目的质量撑不起期待。更值得警惕的是回灌效应：用 AI 开发的人越多，未来语料中的平庸代码就越多，模型的开发能力就越平庸——一条自我强化的下行螺旋。

连锁反应已经写在行业上：低级任务被 AI 包办，新人失去了借小事积累经验与眼光的阶梯，编程入行的门槛被拉向天花板；高级程序员愈发稀缺，甚至可能出现断代。

学习的本质，是用自己的模型去预测和判断发生的事情；错了，就设法找出原因、修正模型——知识与能力由此生长。背记信息只证明记忆力好，并不证明学会了；每个用心的小孩都能记住很多东西，而多数人步入社会后「不会学习了」，恰恰因为我们一直把记忆力好误当成会学习。

理解了学习的本质，也就理解了 AI 的正确位置：高效、克制、有目的地使用它——让它执行你想清楚的方案，而不是替你想清楚方案，把省下的心智投入真正的学习。否则，编程新手永远成不了高手，只会被工具牵着鼻子走，在无尽的试错中耗尽算力与时间，自己却得不到丝毫成长。
